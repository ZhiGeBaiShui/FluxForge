# 薇拉的医院合同：游戏内对白稿 v1

> **当前代码不使用本文台词。**
> 用户指定本轮使用 [story-v5-all-text.md](story-v5-all-text.md) 的 2 / 3 / 4 节；
> 本文只保留为设计记录，避免继续误用。
> 当前节奏已改为签约 +3 送原料、+7 取货。

> 范围：只写对白、选项、每段触发条件。不改代码，不新增剧情线。
> 底稿：[story-v5-all-text.md](story-v5-all-text.md) 的 1 / 1.1 / 1.2 不动；本文替换其中的「2. 医院周合同」「3. 周三送原料」「4. 周六取货」。
> 不在本文范围：合同续签、质量复核、合同暂停、帮派退出一类旧链。
> 台词一行一条，可直接做成常量。括号只标极轻语气，游戏不演出 NPC 动作。
> 薇拉：上层区中心医院的医学研究者，兼管采购。句子短，说事，不寒暄。
> 玩家：店主。不是英雄，也不是受害者。

## 0. 场景索引

| # | 场景 | 触发 | 频次 | 玩家可拒绝 | 声望 |
|---|---|---|---|---|---|
| 1 | 合同提议 | 首次高浓度问话之后的下一次到访 | 一次性 | 可 | 不变 |
| 2 | 每周送原料 | 签约日 +7 天，每 7 天 | 每周 | 可 | 不变 |
| 3 | 取货·未达标 | 签约日 +3 天，每 7 天 | 每周 | 无 | 下降 |
| 4 | 取货·达标 | 同上 | 每周 | 无 | 上升 |
| 5 | 取货·超额 / 高纯度 | 同上 | 每周 | 无 | 上升（有上限） |

场景 3 / 4 / 5 是同一次到访的三套结果台词，由代码按本次结算选一套。

以下 `offer.01` 这样的编号是行号；进代码时统一加前缀 `vera.hospital.`。

## 1. 合同提议与签约

`offer.01` 薇拉：有件事和你谈。

`offer.02` 薇拉：这次不是零买。

`offer.03` 薇拉：我在上层区的中心医院做药，采购也归我。

`offer.04` 薇拉：医院的供应商换了两家，浓度都不稳。

`offer.05` 薇拉：上次那批我拿回去测过。你的能用。

`offer.06` 薇拉：医院想找个固定的供货方。

玩家选项：

1. 行，我做。
2. 怎么供？
3. 不了。

### 1.1 问细节

`detail.01` 薇拉：每周一批。

`detail.02` 薇拉：酸、碱都行，九成以上，越纯越好。

`detail.03` 薇拉：量够医院用一周的。

`detail.04` 薇拉：之后我先送料，你做完，我来取。

`detail.05` 薇拉：货我看过，再算钱。

`detail.06` 薇拉：交不够，钱按交的算。医院那边会记一笔。

玩家选项：

1. 行，我做。
2. 算了。

### 1.2 接受

`accept.01` 薇拉：那从今天算。

`accept.02` 薇拉：三天后我来取第一批，用你自己的料。

`accept.03` 薇拉：下周我把原料带过来。

【系统】医院合同开始。

### 1.3 拒绝

`decline.01` 薇拉：行，那还照旧。散货我照收。

直接拒绝和问完细节再拒绝，共用这一句。

### 1.4 设计注

- 触发：`vera.high_purity_dialogue_done == true`，且不是 1.1 那次到访，而是紧接着的下一次到访。
- 一次性：`hospital.contract.offered`。拒绝写 `hospital.contract.declined`，之后不自动再提；本文不写重开入口。
- 签约动作：注册医院 faction，合同从当天起算，声望 0 开始。
- 提议和拒绝都不改声望。拒绝后日常收购照旧。
- 不出现：病人、家属、姐姐、诊所、「预算不够」、「我知道你们下环不容易」、「你不签我就没货」。
- 不报价目表、不报分数线、不说「三百毫升」这类量词。目标量由结算界面显示，不在台词里。
- 她不懂下环怎么活，表现为不评价店面、不问生意难不难、不给建议。善良落在做法上：原料不收钱、剩料自己带走、不追问。
- 「交不够，医院那边会记一笔」是她能说的最重的后果，不加「次数多了会怎样」。暂停合同属于旧稿，v1 不写。

## 2. 每周送原料

`mat.01` 薇拉：这周的原料。

`mat.02` 薇拉：医院用剩的。浓度不够，杂质不少。

`mat.03` 薇拉：原料不要钱。

`mat.04` 薇拉：用不上就直说，我拉回去。

玩家选项：

1. 都留下。
2. 我挑几瓶。
3. 这周不接。

全收：

`mat.all.01` 薇拉：行，都在这。

`mat.all.02` 薇拉：下周还是这天。

部分收：

`mat.part.01` 薇拉：行，剩下的我带回去。

`mat.part.02` 薇拉：下周再带一批。

不接：

`mat.none.01` 薇拉：行，我带走。

`mat.none.02` 薇拉：那下周再看。

### 2.1 设计注

- 触发：签约日 +7 天，之后每 7 天。判定用 `(day - startDay) % 7 == 0` 且 `day > startDay`。
- 每周一次。2–4 瓶受污染酸/碱，瓶数和污染程度随医院声望，具体值走常量。
- 全收、部分收、不接都不改声望。不接就是等下个送料日，不补一句安慰，也不留一句暗示损失。
- 玩家选不接时不给任何提示。若产品上必须有反馈，用一行系统文本「本周未收原料」，不让薇拉解释规则。
- 不出现：乞求、道德绑架、「这些原料很贵别浪费」、抱怨下环、替玩家算账。
- 台词的「下周还是这天」指送料日，不写具体星期几，免得和取货日撞。
- 本文只写酸/碱。如果 ChemicalRequest 以后加酒精，`mat.02` 的措辞要同步，不要在台词里一次列全所有品类。

## 3. 每周取货·未达标

本次得分低于目标。含零交付。

开场，三档共用：

`pick.hello.01` 薇拉：来取货。

未达标，有货但不够：

`pick.short.01` 薇拉：这周不够。

`pick.short.02` 薇拉：钱按你交的算。

`pick.short.03` 薇拉：差的部分我先记下。

【系统】医院声望下降。

零交付（柜台上没有可交的货）：

`pick.zero.01` 薇拉：这周没有？

`pick.zero.02` 薇拉：行。

`pick.zero.03` 薇拉：下周我来看看。

【系统】医院声望下降。

### 3.1 设计注

- 触发：签约日 +3 天，之后每 7 天。判定用 `(day - startDay) % 7 == 3`。
- 每周一次。首周取货在 +3，玩家用的是自己的料；原料要到 +7 才到。
- 取货走合同结算流程，检查后柜台，台词只按本次结果选一套。计分以代码方案第 7 节为准。
- 零交付同样算未达标，走 `pick.zero` 那一套。
- 档位默认按得分分；高档位允许由得分或纯度两者任一触发，阈值做成常量。
- 付款：按得分折算（0.5 信用点 / 分），未达标照付已交部分，只体现为「钱按你交的算」和入账提示，不报单价。
- 声望：按缺口下降，零交付照扣。数值走结算，只出系统通知，不进台词。
- 不出现：分数、缺口数字、单价、「你让我很失望」、叹气、「下不为例」、「再这样合同就停」。
- 她记的是账，不是人情。不加「我帮你顶了」这种替玩家担责的话。

## 4. 每周取货·达标

得分达标，但没进高纯度档。开场沿用 `pick.hello.01`。

`pick.ok.01` 薇拉：够了。

`pick.ok.02` 薇拉：这批我带走。

`pick.ok.03` 薇拉：下周照这样。

【系统】医院声望上升。

### 4.1 设计注

- 触发同上，和 3 / 5 互斥，由本次结算选一套。
- 达标档最容易写成表扬，这里只确认结果：够了、带走、下周继续。不加「做得不错」「我就知道你可以」。
- 声望按得分折算后加上去，单次有上限；台词不体现数值。
- 不出现：夸奖式评价、拍肩、承诺长期合作、提价承诺（那是续签线，v1 不做）。

## 5. 每周取货·超额 / 高纯度

得分明显超出目标，或本次有 99.5% 以上的液体。开场沿用 `pick.hello.01`。

`pick.high.01` 薇拉：比我单子上要的多。

`pick.high.02` 薇拉：纯度也高。

`pick.high.03` 薇拉：多的部分我按一样的价收。

`pick.high.04` 薇拉：医院那边好交代。

【系统】医院声望上升。

### 5.1 设计注

- 触发：得分进入高档阈值（建议做成常量），或本次交付里出现 99.5% 以上的液体。二者取其一即可，实际阈值由常量定。
- 三档台词只决定说法，不改结算。声望永远按得分算，单次正上限 +20。
- 「医院那边好交代」是她自己的处境，不是给玩家的奖励说明。不要展开成医院内部压力，那是旧稿的续签/复核线。
- 不出现：惊叹、「你怎么做到的」（1.1 已经用过一次，不重复）、纯度术语、权值、加分说明。
- 不承诺以后都收这个品质，也不加价。

## 6. 写法红线（全篇适用）

- 禁用词：深吸一口气、眼中闪过、嘴角勾起、仿佛、不禁、缓缓开口、顿了顿、微微、沉默片刻。
- 不写玩家看不见的动作：没有「她把清单推过来」「他数了数钱」。台词里可以提物件，但不写动作过程。
- 不写作者解释：不写「她其实是在帮玩家」「这一句是给玩家留的退路」。
- 不连续三句同一结构。不排比。不总结。不升华。
- 每句只做一件事：说结果、说要求、说下次。原因由玩家自己拼。
- 玩家选项不加情绪标注，不加「（会扣声望）」这类系统提示。
- 付款和声望只有两个出口：薇拉一句结果，加一条系统通知。旁白不替她算账。

## 7. 和旧稿的差异（整合用）

| 项 | 旧稿 all-text | 本文 |
|---|---|---|
| 送料 | 周三 | 签约日 +7，每 7 天 |
| 取货 | 周六 | 签约日 +3，每 7 天 |
| 首周顺序 | 先送料，后取货 | 先取货（自备料），再送料 |
| 未达标 | 换货 / 欠着 / 争辩 / 首次求情 | 不换货不欠账，照付已交部分，扣声望 |
| 结算口径 | 10 信用点 / 100 mL | 按得分折算，0.5 信用点 / 分 |
| 声望 | 达标 +4，未达标 -8 | 得分 / 100 加（上限 +20），缺口 / 100 扣 |
| 复核、续签 | 有 | 不在 v1 |

## 8. 待确认

1. 拒绝之后有没有主动重谈入口。本文只写了「不再自动提」。
2. 首周取货在 +3，玩家可能来不及备货。要不要首次豁免，或把首次取货顺延到 +7 之后。
3. 不接原料本身不扣声望，但下一次取货会缺料，仍然要扣。要不要在文案或界面里提示这一层。
4. 单次正声望上限 +20，负声望有没有下限，尚未定。
5. 结算界面要不要显示目标进度。台词不报数，玩家只能从界面看。
