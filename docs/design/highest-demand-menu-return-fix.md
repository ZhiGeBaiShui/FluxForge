# 60声望请求返回交货菜单修复

游戏内症状：选择“可以。”后出现空白薇拉对白，交货菜单无法正常继续。

原路径是收货开场的插入点调用请求子图，决策边结束后返回父图。`StoryPlayer.BuildNext` 在子图末尾通过续接桥恢复父图，而父图此时只有菜单、没有后续对白，进入 `tail == null` → `StoryDialogueAdapter.BuildOptions`，创建空标题空文本的对白。这是实际代码路径，不是推测空指针或存档损坏。

旧测试只断言菜单Choices存在，无法证明原版UI能显示空白对白上的菜单。新测试 `HighestDemandDecisionReturnsToDeliveryOnVisibleNpcResponse` 对接受/拒绝分别断言：最后一条实际对白是指定回复、非空，同时挂有普通交货和结束选项，且可实际提交并结算。

修复采用已有图连接能力：`HospitalHighestDemandOfferAssembly.CreateOptions(returnTo)` 构造请求选项，两个决策边直接连接本次普通交货菜单。收货开场按是否需要提出请求选择问候及下一节点。没有修改通用播放器、空白菜单适配或新增防御兜底；没有增加新的存档字段。

提出请求时仅播放“你好，这次有个额外的请求。”及原四句请求，不先说“我来取这周的货。”。接受、拒绝使用用户指定的后续对白。其他收货日沿用原问候。已删除不再使用的PickupStarted插入点。
