## 迭代结果

1. **修复快速跳过失效。** 原版 DialogUIManager.cs:347 先清掉 skip 标志，:351 再传入 0.01f；
   原补丁读标志无法识别跳过。现在识别实际调用参数。先运行新增测试复现 0.01 秒被覆盖为 2 秒，
   再修复；另两个测试确认普通自定义停顿和原版行保持正确行为。
2. **移除立绘中没有真实路径依据的恢复代码。** 缓存中只写入成功创建的 Sprite，销毁后立即清表；
   没有查到额外外部销毁路径。删掉这些空值兜底和统一 catch(Exception)。
   外部贴图来自 ModLoader 文件枚举，缺资源返回有明确输入边界，保留对应日志和跳过处理。
   后续原版证据复核发现 GetPool 明确允许字典未初始化，已恢复 Apply 的初始化判空，
   Shutdown 注销键时采用相同边界判断。此前删除这项检查的结论已撤回。
3. **统一立绘资源释放。** Shutdown 同时注销自己写入的 SpriteDict 键并销毁生成的 Sprite、纹理，
   不把尚未证明存在玩家触发路径的所有权瑕疵夸大为游戏故障。
4. **删除重复条件。** 薇拉 20、40 声望事件已有 MaxTimes=1，移除各自重复的 SeenCount 判断；
   保留 20 事件对 40 事件的跨事件检查。新增两个回归用例验证不重播、不补播低阶段。
5. **统一状态读取与说明。** VisitCount 改为同类已有的 TryGetValue 风格，避免查两次字典；
   IStoryState 明确是读写契约，作者文档明确 Condition 只能读取状态，不能在求值时付款或写标记。

短回调、调用栈、弱引用停顿表等有具体职责的机制保留；没有为减少语法增加新类、接口或服务。
暂未被现有剧情消费的交易字段、状态作者 API 如实标注覆盖范围，没有把接口声明冒充生产使用。

## 如何检查记录是否对应当前代码

在仓库根目录执行：

```powershell
python docs/design/story-line-audit/verify.py
```

脚本核对预期文件清单、重复文件、每份文件从第 1 行至末行的连续覆盖、记录理由和证据，
并核对源码字节 SHA-256。代码再修改后，哈希不一致会使检查失败，需要重新审查对应文件。
它验证记录完整性，不能替代人工判断语义正确性。
