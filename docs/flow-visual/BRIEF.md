流源数据（设计时可假设可拿到）：成分占比（水/毒/油/血/酸/能量，0..1）、温度（℃，-20..100）、
总含量（µL，0..50 000 000，1 mL = 1000 µL）、当前位置（整数格）、方向（4 向）、速度（格/秒）、
剩余射程（格）、状态（流动/受阻/分流/汇聚/被收集/静止）。

## 2. 任务

从零设计**「流源」这个实体在 16px 网格中的视觉语言**。

- 参考「背包英雄」(Backpack Hero) 的机器人/能量流**理念与观感**——像素密度、明暗层次、动效节奏；
  **不复制任何素材**，所有图形自行生成。
- 用什么手段由你决定：像素精灵、顶点矩形、程序化贴图、粒子、拖尾、符号、发光叠加……
  **旧实现（粒子场 v2）整份作废，不要继承它的任何参数或代码结构。**
- 最终必须是一套**可被另一名工程师照着实现在 UGUI 顶点层**的规格，而不是 mood board。

## 3. 玩家必须能读出的 6 条信息

| # | 信息 | 取值 | 玩家要做的判断 | 可观察性要求 |
|---|---|---|---|---|
| I1 | 成分 | 水/毒/油/血/酸/能量（可混合） | 「这是什么」 | 1x 下 6 色可分；色盲模拟下至少 4 组可分 |
| I2 | 温度 | 冷 / 常温 / 热（连续 -20..100） | 「会不会冻住 / 烧起来」 | **静态帧**即可读，不依赖动画 |
| I3 | 含量 | 空 → 50 L，至少 3 档 | 「还有多少」 | 3 档静态可辨；"少"不能读成"散" |
| I4 | 射程 | 剩余可走格数，至少 3 档 | 「还能撑多久」 | 与 I3、与尾迹长度不冲突 |
| I5 | 状态 | 流动 / 受阻 / 分流 / 汇聚 / 被收集 | 「发生了什么」 | 静止画面也能看出 |
| I6 | 方向 | 上/下/左/右 | 「往哪走」 | 4 向都成立，拐弯不出现错位感 |

可加的信息（可选，不占必需通道）：速度、混合比例、是否首次生成、剩余寿命。

## 4. 硬约束

- **C1 像素纪律**：16px 格；轴对齐；整数像素；禁止抗锯齿 / 模糊 / 任意角旋转；
  半透明边缘 alpha ≥ 1（游戏的点击命中阈值 1e-5）。
- **C2 一属性一通道**：同一视觉量不得同时编码两个属性。
- **C3 禁止粗细编码**：任何属性的表达都**不许**改光束/主体的宽度、芯宽、亮带厚度、上下厚度
  （历史两次被否，见 §5）。
- **C4 温度静态可读**：不靠动画、不靠"飘动方向"单独承担；静态帧必须能分出冷/常温/热。
- **C5 不遮图标**：流源画在 12×12 图标之上；关键信息不能被整块不透明区域长期盖住。
- **C6 技术边界**：只用 UGUI 顶点矩形 / 程序化纹理 / 默认 UI 材质；**不依赖自定义 shader、后处理、URP**。
- **C7 预算**：单流源 ≤ 64 quads（或等效 1 次 draw call）；稳态 **0 GC alloc / 帧**；不每帧 new 材质。
- **C8 4 向成立**：上/下/左/右 + 运动/静止/受阻都要成立；L 型路径不出现"错台"。
- **C9 合法性**：不复制游戏或背包英雄的任何贴图/音频；引用只取理念；交付物全部自绘/程序生成。
- **C10 动效不得误读**：不能让人看成卡顿、掉帧、穿模、渲染 bug。

## 5. 历史否决清单（不要重犯）

| 被否方案 | 否决原因 |
|---|---|
| 8px 宽光束 | 半个格子，直接压住 12×12 图标 |
| 温度 = 垂直于流轴的 ±2px 位移 | 四方向对"垂直"定义不同；L 拐角断带；读成对齐 bug |
| 温度 = 亮芯宽度 / 强度 = 宽度 / 含量 = 宽度 | 都是"改粗细"，语义互撞 |
| 头部纯白 | 全场最亮点抹掉成分色 |
| 8×8 角块内走 L | 拐角变成和 T 型节点一样的亮方块 |
| 每格 1px 虚线表射程 | 与状态边框、温度抢同一圈 1px；全图描边 = 零信息 |
| 温度 = 散开度 | 读成"散"而不是"冷/热" |
| 粒子"少" = 稀疏长尾 | 应读成"短而实"，不是"散" |
| 弧长 16px 的头部 | 像素尺度下坡度 17°，量化成一长条平台；**7px / 45° 才读得出** |
| 4px 方块 + 2px 柔化环 | 脚印 6px，小于 5.2px 弧深，把形状全吃掉 |

**像素尺度铁律**：渐变与"看不见"是同一件事；要读得出的变化必须在 1–2 像素步内完成。

## 7. 评审 rubric（每项 0–2 分，任何 0 分项即不可交付）

| 项 | 0 | 1 | 2 |
|---|---|---|---|
| 1x 可读性 | 认不出是什么 | 勉强 | 一眼可分类 |
| 温度静态可读 | 只能动起来看 | 需对比 | 单帧可判 |
| 成分可分 | 颜色接近 | 4 组可分 | 6 组 + 色盲 4 组 |
| 含量可分 | 只能靠动画 | 2 档 | 3 档静态清楚 |
| 通道正交 | 两属性抢一个量 | 轻微重叠 | 完全正交 |
| 像素预算 | 超 64 quads / 做不到 | 勉强 | ≤ 32 quads 也能成立 |
| 动效可信 | 像卡顿/穿模 | 平淡 | 有生命感且不误导 |
| 4 向一致 | 某方向崩 | 轻微 | 完全一致 |
| 实现风险 | 要 shader/改逻辑层 | 有坑但可绕 | 纯顶点即可 |
| 可测试性 | 无法验收 | 部分 | 每项都有可观察判据 |

## 8. 必须回答的开放问题

1. 流源是「实体」（有固定轮廓的小物件）还是「流体」（形态随属性变形）？这决定整套形态语言。
2. 是否需要方向性头部？如果需要，头部形状怎么在 4 向复用而不错位？
3. 含量用「体积」还是「内部密度/亮度」表达？哪个更像"多少"而不是"散"？
4. 射程用哪条通道，才不会与尾迹长度（含量/速度）打架？
5. 6 种成分是否需要在**颜色之外**再给形状差异（例如酸=锯齿、毒=气泡）？
6. 流源在同一格停留、以及被阻挡时，如何在不改逻辑层的前提下表达"不动了"？
