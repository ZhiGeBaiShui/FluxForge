# 参考研究：背包英雄（Backpack Hero）的像素视觉语法 → 能给"流源"借什么

> 作者：参考研究员　｜　日期：2026-10-20　｜　范围：只读研究，未改动任何代码/素材
> 关联：[BRIEF.md](../BRIEF.md)（约束 C1–C10、否决清单、rubric）
> 标注约定：**【实锤】** = 我看到了页面原文/像素数值，可复现；**【推断】** = 由机制或几何推出的判断，未直接观测。

## 0. 结论先行（5 句）

1. 背包英雄的像素语法可以压成一条公式：**16px 网格 + 1px 近黑紫描边 #292234（L≈37）+ 每材质 3–4 阶明暗 + 最亮阶封顶在 #D5D2B8（L≈209，不用纯白）**。8 个物品美术文件中 7 个符合这条公式（唯一例外是玻璃水瓶，它有意不用描边）。
2. 它的物品**不是"缩在格里"，而是"填满格、只留 1–3px 出血位"**：实测可见轮廓 12×22 / 14×54 / 22×29 / 26×42 px，均贴着自己格子的边。这与"我们的图标 12×12 居中、四周留 2px"是同一套数学（16−2×2=12）。
3. 它**没有统一光源**：8 个素材里亮部质心偏上 4 个、偏下 2 个、基本居中 2 个，左右也各占一半。这一点**不能借**——流源要跨格连续，光源必须唯一，否则 L 拐角会读成两个物件。
4. CR-8 的"能量"在机制上是**每格一停、四向推进、边走边消耗**的实体（【实锤】wiki），和我们的流源同构；这直接决定动效应是**阶跃**（8 帧/格）而不是连续流光。
5. 公开资料里**没有**对 CR-8 激光/电荷像素外观的第一手文字描述（wiki 只给机制、数值和 16×16 图标）。任何"光束多粗、什么颜色"的说法在本文件里都是【推断】，设计时不要当既定事实引用。

## 1. 背包英雄的视觉语法

### 1.1 像素密度：16px 是一切的公约数【实锤】

- 工作区 `assets/raw/reference/` 下 18 个 PNG（8 个物件美术 + 4 个纯 mask + 3 张图集 + 3 张放大/裁剪），尺寸全部是 16 的整数倍：`16×16`、`16×32`、`16×64`、`64×32`、`32×32`、`32×48`、`32×64`、`48×16`、`48×32`。**没有一个非 16 倍数**。
- 背包英雄 Wiki 的 `Energy.png` 原图是 **320×320**，320 = 16×20 → 图标本体极可能是 **16×16 的 20 倍放大导出**【推断，算术推断，未见原始文件】。
- CR-8 的待机 GIF 是 **80×148 px**（Wiki 文件页 `data-file-width/height`）【实锤】——即宽 5 格、高约 9.25 格，面积 ≈46 个 16×16 格：**英雄远大于物件**，这是它的尺度分层策略。
- 外部评测把整体风格描述为"16-bit 时代的像素风"【实锤，属评测者措辞】。

**对我们的意义**：16px 不是我们的妥协，而是这一类型的标准工作分辨率。**不要往 32px 密度靠**，那会让 1x 下的 1px 细节全部消失（BRIEF 铁律：渐变＝看不见）。

### 1.2 轮廓策略【实锤，逐像素测量】

- **描边颜色**：`#292234`，sRGB(41,34,52)，相对亮度 L≈37。8 个美术文件里 **7 个**的最暗色就是它；剩余 1 个（`large_blue_100_ORIGINAL.png`，玻璃水瓶）**完全没有描边**。
- **不是纯黑**：L=37，比 `#000000` 亮 37 级。这一点很关键——纯黑描边在暗背景上会变成"洞"，近黑紫描边仍然保留材质感。
- **厚度 = 1px**：在可见轮廓的边界上，暗色（L<60）像素占比为
  `ref_long_module1` 92%、`ref_med_bottle_orange` 75%、`juice_pouch` 51%、`beis_icecream` 49%、`ref_module_yellow_c` 38%、`items_food_juice` 39%、`glass_shard` 15%（斜向轮廓，抗锯齿不可用，只能断开）。
  → **直边处描边闭合，斜边处允许断点**，这是 1px 硬描边在像素画里的必然代价，不是失误。
- **剪影可读性**：所有物件在 1px 描边内都是完整闭合的单一形体，没有内部"碎块"；`glass_shard` 是唯一例外（玻璃碎片，形状本身就是信息）。
- 描边与内部最亮色的对比度：`#292234` vs `#D5D2B8` = **10.0:1**（WCAG 相对亮度）；若换成 `#241E2E`（L=32）则 **10.6:1**。

### 1.3 明暗阶数：2 阶太少，3–5 阶是常态【实锤】

按亮度排序后的**单物件调色板阶梯**（实测）：

| 素材 | 色数 | 亮度阶梯 L（由暗到亮） | 步长 |
|---|---|---|---|
| `glass_shard.png` | 5 | 37 → 115 → 143 → 179 → 209 | 78 / 28 / 36 / 30 |
| `large_blue_100_ORIGINAL.png` | 5 | 97 → 135 → 175 → 224 → **255** | 38 / 40 / 49 / 31 |
| `ref_med_bottle_orange.png` | 8 | 37 → 85 → 90 → 117 → 120 → 145 → 172 → 209 | 密集中段 |
| `beis_icecream.png` | 10 | 37 → 52 → 53 → 78 → 97 → 115 → 128 → 143 → 179 → 195 | 15–36 |
| `ref_module_yellow_c.png` | 12 | 37 → 56 → 65 → 103 → 110 → 120 → 144 → 151 → 167 → 185 → 195 → 208 | 7–38 |
| `ref_long_module1.png` | 13 | 37 → 52 → 65 → 78 → 93 → 93 → 103 → 110 → 120 → 151 → 167 → 185 → 195 | — |
| `items_food_juice.png` | 14 | 37 → 53 → 72 → 77 → 88 → 102 → 110 → 135 → 145 → 167 → 167 → 172 → 208 → 209 | 5–33 |
| `juice_pouch.png` | 19 | 37 → 49 → 52 → 70 → 78 → 85 → 89 → 102 → … → 209 | 3–20 |

**读法**：
- **描边 1 阶 + 形体 2–4 阶** 是主流。`glass_shard` 给出最干净的例子：**5 色＝1 描边 + 4 阶玻璃**，每阶步长 28–36 L。
- **单步明度差小于 25 就白做**：肉眼看不出（对应 BRIEF 的"1–2 像素步内完成"）。
- **最亮阶不用纯白**：7/8 个素材的最亮色落在 L=195–209（多为 `#D5D2B8`/`#E0D09B`），只有玻璃水瓶用了 `#FFFFFF`(255)，且它是"内容/液体"的角色。
- **光源方向不统一**：亮部质心相对几何中心的偏移，偏上 4 个（`ref_module_yellow_c` Δy=−1.9、`beis_icecream` −3.3、`juice_pouch` −1.4、`items_food_juice` −3.3），偏下 2 个（`glass_shard` +1.3、`large_blue_100` +2.5），基本居中 2 个（`ref_med_bottle_orange` ±0.0、`ref_long_module1` −0.2）；左右同样对半分。**结论：物件自带局部光，没有全场统一光。**

### 1.4 调色板规模：5–19 色/物件，中位数 11【实锤】

实测（可见像素 α≥128 的唯一色数）：`glass_shard` 5、`large_blue_100` 5、`ref_med_bottle_orange` 8、`beis_icecream` 10、`ref_module_yellow_c` 12、`ref_long_module1` 13、`items_food_juice` 14、`juice_pouch` 19。
跨 512×512 图集的**全局色数**也只有 33–73 色——它用的是一张**很小的共享调色板**，靠复用而不是每物件新调色。

**对我们的意义**：BRIEF 的 `≤64 quads / 单流源` 预算，换算成色数就是"**一个流源最多 4–5 个色值**"。色数超标往往不是美术需求，是没做减法。

### 1.5 图标在格里的占比与留白【实锤】

| 素材 | 画布 | 可见轮廓 | 左/右/上/下留白 |
|---|---|---|---|
| `ref_med_bottle_orange` | 16×32 | 12×22 | 2 / 2 / 5 / 5 |
| `ref_long_module1` | 16×64 | 14×54 | 1 / 1 / 5 / 5 |
| `juice_pouch` | 32×32 | 22×29 | 5 / 5 / 2 / 1 |
| `items_food_juice` | 32×48 | 26×42 | 3 / 3 / 3 / 3 |
| `ref_module_yellow_c` | 32×32 | 28×31 | 3 / 1 / 0 / 1 |
| `beis_icecream` | 48×32 | 42×31 | 3 / 3 / 1 / 0 |
| `glass_shard` | 48×16 | 46×14 | 1 / 1 / 1 / 1 |
| `large_blue_100` | 32×64 | 18×52 | **7 / 7 / 3 / 9** |

- **横向规律最硬**：单格宽物件（16px 画布）可见宽 12–14px，即**每侧留 1–2px**。这与 BRIEF 的"物品图标 12×12 居中"完全同构。
- **纵向允许出血**：长条物件（16×64）上下只留 5px，即**吃掉相邻行的视觉空间**来表达"这是个长东西"。
- **特例**：`large_blue_100` 是细长玻璃瓶，横向只占 18/32 = 56%——因为它的形状信息在纵向一致性，不在横向占满。
- **命中区是满格的**：所有素材的完整画布都被 `#000000`、**alpha=1** 的隐形像素填满（`ref_water_bottle.png` / `ref_pill_bottle.png` / `ref_water_off.png` / `water_bottle.png` 四个文件更是**整张只有 alpha=1 的纯黑**，1024/256/2048/1024 像素）。这说明背包英雄把**"美术"和"占格/命中"分成两层**：画的是 12–14px，占的是整格。这正好解释了 BRIEF 里"点击命中阈值 1e-5"的存在。

### 1.6 CR-8 的能量 / 射线 / 流，在公开资料里到底长什么样

**能查到的（机制层）【实锤，Wiki `backpackhero.wiki.gg/wiki/CR-8`，页面最后编辑 2024-09-16】**：

> "CR-8 starts with a Core that on use, creates a charge of **3 base Energy** … Each charge **travels in a cardinal direction**, using any item it travels through. If the item costs Energy, the charge will **lose Energy equal to that cost**. After consuming all Energy from the Charge, it will disappear, and any other active charges will fire. If all charges disappear, your turn will end."

同页 Tips 补充：`charges use items each tile they travel on`；独占物品 `Ray Gun` **依赖 charge 的移动距离**（"depend on charge travel distance"）。另据同页，CR-8 的升级用**俄罗斯方块形状的拼块**而不是单格。

**由此可确认的三件事（对"流源"直接可用）**：
1. **它是"1 格实体逐格推进"，不是连续水流**——和我们 BRIEF §1 的流源定义**完全同构**。
2. **射程是天然属性**（能量耗尽即消失，Ray Gun 的强度与走过的格数挂钩）→ 我们 I4「射程」有先例，且它的表达方式是**"还能走几格"而不是"光有多长"**。
3. **它会"用掉"沿途的东西**（每格触发一次物品）→ "流源经过一格 = 与该格发生一次交互"，这是动效节奏的叙事依据。

**查不到的（外观层）**：
- Wiki 只有 `Energy.png` 图标（320×320，即 16×16 的放大）和一个 `Cr-8_Idle_Gif.gif`（80×148），**没有任何一句描述电荷/射线在屏幕上的粗细、颜色、粒子、头部形状、帧率**。
- Steam 商店页与 Shacknews 访谈在本环境取回失败（`store.steampowered.com` fetch failed；shacknews 403），因此**没有拿到开发者对光束外观的原话**。

**因此以下全部是【推断】，请勿当事实引用**：
- 【推断】电荷本体占 **1 格（16×16）**：因为"每经过一格用一次物品"是逐格判定，视觉上必须和格子对齐，否则玩家无法预判触发次数。
- 【推断】射线是**格对齐的折线（90° 转向）**而不是自由角度：整个背包系统是方块堆叠，任何斜向光路都会与"格"这一唯一坐标系冲突。
- 【推断】电荷必须有**方向性头部**：转向发生在格心，若无头部，L 型路径的拐点无法与静止电荷区分。
- 【推断】头部**不会用纯白**：该作 8 个美术文件里纯白只出现在"玻璃/液体"上，纯白是材质语义而不是"最亮"语义（也契合我们 BRIEF 已否决的"头部纯白"）。
- 【推断】动效是**阶跃式**：一格一停（受击/触发反馈需要可读的停顿），而不是匀速滑动。

> 可验证方式（留给后续有屏幕录像的人）：录一段 CR-8 战斗，数"电荷跨一格用了几帧"。我这边没有录像源，不做数字断言。

## 2. 本作基线：`assets/raw/reference/` 的像素语言（逐像素实测）

> 说明：BRIEF §9 称这些为"现有参考图"。它们是否就是本作线上图标，我无法从工作区自证；但其网格对齐、色板与背包英雄高度一致，**按"本作基线"使用是安全的**。

### 2.1 硬指标

| 项 | 实测值 |
|---|---|
| 描边 | `#292234`，1px，7/8 素材采用；**非纯黑**（L=37） |
| 最亮常用色 | `#D5D2B8`（L=209，暖白）；纯白 `#FFFFFF` 只出现在玻璃瓶中（252 px） |
| 单物件色数 | 5–19（中位 11） |
| 典型明暗 | 描边 1 阶 + 主体 2–4 阶，步长 ≥28 L |
| 典型尺寸 | 单格件 12–14px 宽；长条件 14×54；多格件 22×29 / 26×42 |
| 留白 | 横向 1–2px/侧（单格件），纵向可压到 0–1px |
| 命中层 | 整张画布满铺 `#000000`、alpha=1 的隐形像素（4 个文件是纯 mask） |
| 光照方向 | **不统一**（见 §1.3） |
| 对比度 | 描边 vs 亮面 = 10.0:1 |

### 2.2 和我们现有约束的对照

- **BRIEF 说"物品图标典型 12×12 居中"，参考实测"单格件 12–14px 宽"** → 一致，**2px 出血位是原生惯例，不是我们抠出来的**。流源画在图标之上时，**真正可用的"安全不遮挡区"只有四角的 2×2**（16 格 − 12 图标 = 每角 2×2）。
- **本作基线也没有统一光源** → 流源若引入固定左上光，会是**全场唯一有光源方向的物件**，反而变成可辨识特征（可借，见 §5 R1），但也意味着不能指望图标"配合"光影。
- **纯白在本作是"玻璃/液体"语义** → 流源用纯白当头部会与"容器里有水"混淆，且已被 BRIEF 否决两次。

## 3. 可借鉴的 5 个具体装置（每条一句可执行）

1. **用 1px、`#241E2E`（L=32）的近黑紫描边完整包住流源主体**，别用纯黑；对比度对 `#D5D2B8` 达 10.6:1，保证在任何物品图标底色上剪影成立。
2. **把最亮阶封顶在 L≈205（`#D5D2B8`），纯白（L≥240）只留给"能量/高温"的瞬态帧**，这样"变白"本身成为语义，不会和成分色抢通道。
3. **主体只占 10×10（核心 6×6 + 四向 2×2 指节），四角各留 2×2 给底下的图标透出来**——这是"不遮图标"（C5）在同尺寸下唯一算得出来的解。
4. **每个材质给 3 个阶梯色，单步明度差 ≥28 L**（照抄 `glass_shard` 的 37/115/143/179/209，实测间距 28–36），少于 3 阶读不出体积，多于 4 阶在 1x 下糊成一团。
5. **用"横向亮带"而不是渐变表达内部界面**（`large_blue_100` 的做法：整段实色带 + 1px 亮分界线），因为它量化后仍保持 1px 清晰，而渐变在 16px 下等于没有。

## 4. 不可借鉴的 3 个（+1 条补充）

1. **多格大件的细节密度（48×32、80×148 英雄）——不是版权问题，是网格问题。**
   背包英雄的英雄精灵 80×148，是 **46 个 16×16 格**的面积；【推断】它脸部的信息量压到单格 16px 里只剩 4–6 个可读像素。**照搬密度 = 1x 下全是噪点**，且直接撞穿 C7 的 64 quads 预算。

2. **零描边 + 纯白高光的玻璃表现（`large_blue_100`：无 `#292234`、含 `#FFFFFF`）。**
   它成立的前提是**大面积浅色底 + 周围没有别的图形**。我们的流源画在任意物品图标之上（`SetAsLastSibling`，BRIEF §1），无描边的浅色形体与 12 色图标混在一起会直接消失——这也正是 BRIEF 已否决的"头部纯白"。

3. **整份调色板/贴图搬运（含 `#292234` 这个具体值的整套用法）。**
   C9 明确不能复制素材；此外它单物件 5–19 色，是按"整张贴图"组织的，而我们是**顶点矩形**（C7：0 GC/帧、≤64 quads），每多一个色值就多一次材质/顶点色分支。**借的是"1 描边 + 3 阶 + 封顶亮度"这条规则，不是那张图。**

**补充（不计入 3 条）：局部光源不统一。**
   背包英雄每个物件自带光（§1.3），因为它每个物件都是独立贴图。流源是**同一实体跨越连续多格**，光源一换，L 拐角就会读成"两个不同东西拼在一起"（正撞 C8）。所以**必须全场单光源**，这是与参考相反的决策。

## 5. 对流源设计的 6 条启示（全部落到像素/色值/帧数）

**R1｜剪影：10×10 主体 + 1px `#241E2E` 描边 + 四角 2×2 镂空。**
核心 6×6 实心（成分色），四向各伸 2×2 指节，整体落在 16×16 的居中 12×12 内、且四角让出 2×2。描边 L=32、对比 10.6:1，任何底色上剪影成立；四角镂空直接满足 C5 的"不能整块盖住图标"。

**R2｜明度预算：三阶固定 L=40 / 110 / 165，第四阶（L≥205）只做瞬态。**
实测参考的阶间距 28–36，我们取 ≥55 的更大间距（16px 尺度上更稳）。稳态只用前 3 阶；L≥205 的白只在"过热/能量爆"的 2–3 帧出现，避免永久占用最亮通道（BRIEF 否决：头部纯白抹掉成分色）。中阶（L=110）是**成分色**的槽位，允许随温度在 110–128 浮动（见 R3），描边阶与亮阶保持固定。

**R3｜温度：锁明度、改色相，三档六边形值。**
冷 `#407E9C`（L=115）／常温 `#808078`（L=127）／热 `#C9713F`（L=128）——**三档明度差 ≤13 L，肉眼读成"同一亮度、不同温度"**，不会与 I3 含量（明度/填充）抢通道（C2）。再加 1px 形状备份：冷＝主体上缘 1px 平边，常温＝平边+中心 2×2，热＝上缘 3px 锯齿（色盲下仍可读，对应 rubric"6 色 + 色盲 4 组"）。

**R4｜含量：从底部向上填充 3 / 6 / 9 px，分界 1px 亮线。**
在 10×10 占地内以底边为基准，内容高度取 3px（≤1/3，占 30%）、6px（1/3–2/3，60%）、9px（>2/3，90%），顶部留 1px 余量不填。分界用 1px `#D5D2B8`（L=209）**水平实线**，分界以下保持成分色、以上只留描边。选"体积"而非"亮度"是因为参考里横向实色带量化后仍然清晰（§3 装置 5），而亮度编码会和 R2/R3 撞车。**"少"永远是"矮而实"，不是"散"**（对应否决清单"少=稀疏长尾"）。

**R5｜射程：格外的 1×1 射程点（不是尾迹），1/2/3 个，固定间距 2px，绝不接触主体。**
剩余射程 3 档 → 沿**前进方向**在格心之外放 1/2/3 个 1×1 像素点，间距恒定 2px（不随射程拉伸）。因为 C3 禁止粗细编码、且尾迹长度已被含量/速度占用，射程必须走"点数量"这条离散通道；3 个点最远到 x=+7px，仍在半格内，不与下一格的内容混淆。这些点是**前景指示器**、不是拖尾，所以它们在流源静止时也必须存在（静止可读）。

**R6｜动效节奏：8 帧/格 @24 fps（0.33 s/格），落格 hold 2 帧；受阻用 3 帧回弹 1px 后锁死并整体 −20 L。**
对应 CR-8"每格一停"的机制（§1.6）——阶跃而非滑动，玩家才能数清"它经过了几格"。hold 2 帧是防"读成卡顿"（C10）的最小值：1 帧读成掉帧，3 帧读成停顿过长。受阻态不再播推进帧，只播 3 帧 1px 回弹 + 明度 −20（L 165→145），静止帧即可判"不动了"（C4/I5）。
