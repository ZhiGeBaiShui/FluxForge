# 常驻粒子性能评估（2026-10-21）

## 1. 纯逻辑微基准（实测）

用真实 `FlowParticleRules.Build` + `FlowAmbientField` + 列表汇总，64 条流源 × 600 帧（60fps 模拟）：

| 指标 | 结果 |
|---|---|
| 总耗时 | 1.8 ms / 600 帧 |
| 每帧耗时 | **0.0030 ms** |
| 每条流源每帧 | **0.046 µs** |
| 每帧托管分配 | **0 字节** |
| 稳态粒子数 | 64 条 × 4.66 ≈ **298 颗** |

结论：**逻辑层成本可忽略**（0.003ms/帧，约为 60fps 预算的 0.02%）。

## 2. Unity 侧静态成本（估算，未实机 profile）

### 节点数（最坏 64 条流源 / 一块网格）

| 节点 | 数量 | 说明 |
|---|---|---|
| body / edge / accent / wall | 256 | 每源 4 层（wall 仅 blocked；该通道 2026-10-27 起无像素，但节点仍按此规模分配） |
| ghost | ≤384 | 每源 0–6，按含量 |
| dot（粒子） | ≤298（池 512） | 每源 ≈4.7 |
| **合计活跃 Image** | **≈938** | 池对象总计 ≤1152 个 GameObject |

典型 10 条流源：约 40 + 50 + 47 ≈ **137 个 Image**。

### 纹理与显存

| 资源 | 大小 |
|---|---|
| 4 张蒙版 256×1040 RGBA | **4.06 MiB** |
| 粒子 1×1 白贴图 | 4 B |
| Sprite 对象（272 唯一图，按需缓存） | 每张 ~数百 B |

### Draw call

4 张蒙版 + 1 张 1×1 白 = **5 个批次**（同贴图合批；ghost 复用 body 贴图）。

## 3. 真正的风险：Canvas 重建范围

**已处理（2026-10-21）**：`FlowAtlas` 根节点已挂 `Canvas`（不挂 GraphicRaycaster），
每帧重建被限制在流源层内部，不再把背包网格的 Canvas 整体标脏。

代价：流源层自成一个批次边界（5 个 draw call 不变，但不再与背包 UI 合批）；
收益：重建范围与背包物品数解耦。

如果实机仍有开销，按下面第 5 节继续降级。

## 4. 最坏情况估算

- 938 个简单 Image 的重建 ≈ 0.2–0.5 ms/帧（按 UGUI 经验值，未实测）；
- 若不加子 Canvas，且背包里有大量物品，重建成本会随物品数一起涨；
- 加子 Canvas 后，这部分与物品数解耦。

## 5. 建议的缓解措施（按优先级）

1. **加子 Canvas**（1 行，恢复旧的隔离策略）；
2. 粒子池上限 512 → 若同屏流源 > 16 条会截断，可接受；也可按视图限 256；
3. 若实机仍重，把 `SpawnRate` 从 8 降到 6（视觉差别小，粒子数 −25%）；
4. 低配模式：`FlowParticleTuning` 加一个全局开关，关闭粒子只留贴图。

## 6. 复跑

微基准脚本为临时文件，已删除；需要复跑时用 `FlowParticleRules.Build` + `FlowAmbientField` 写一个 xUnit 基准即可（本次方法：64 场 × 600 帧，预热 60 帧后计时）。
