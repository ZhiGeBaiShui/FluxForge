# 盲测协议（可复跑）

> 这套协议是本项目唯一"玩家可读性"的证据来源。所有结论都必须能由它复现。
> 工具：`tools/flow-visual/qa.py`（拼图/色盲）、`score.py`（计分）、`verify.py`（面积/bbox/色板）。

## 1. 准备 tile

- 每张 tile 必须是 **16×16 RGBA、透明背景**（若渲染器输出 64×64 或带底，先 `resize((16,16), NEAREST)` 并抠底）。
- 文件名不重要，**答案只能写在 manifest 里**，不能出现在文件名/图注中。
- `manifest.json`（数组）：
  ```json
  [{"path": "tiles/a.png", "group": "dir", "answer": "up", "meta": "{}"}]
  ```
- 一次只测**一个属性**（一个 group 一张表）。混合 sheet 只能做"整体印象"，不能计分。

## 2. 生成无标注表

```powershell
$py = "C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py tools/flow-visual/qa.py blind --manifest <m.json> --out <sheet.png> --key <key.json> --cols 4 --scale 8
```

- 拼图布局：每格 24×28，顶部 9px 只放编号，tile 在 (4,10)，**编号不压图**。
- 输出 `sheet.png` + `key.json`（编号→答案，评审不可见）。
- 需要色盲测试：`qa.py colorblind --in <sheet> --out <sheet-deutan> --kind deutan --scale 1`。

## 3. 派评审

- 评审必须是**独立 agent**，只看图：
  - 不看 `docs/flow-visual/**` 下的任何 `.md`/`.py`/`key-*.json`；
  - 不看目录名/文件名；
  - 先 10 秒给第一印象，再放大核对；
  - 看不出写 `?`，允许"全部一样难"这种诚实结论。
- 评审只能拿到：图路径 + 选项列表 + 输出格式。不要给设计理由、不要给提示词。
- 两项属性不能放在同一张表里问（会互相提示）。

## 4. 计分

- 与 `key.json` 对比，逐项算准确率。
- 过线：温度 ≥90%、含量 ≥90%、射程 ≥80%、状态 ≥80%、方向 100%（4 向必须全对）。
- 方向只要出现**系统性 180° 反读**（3/4 或 4/4 反向），视为失败，不接受"接近"。
- 记录：评审原话（依据）+ 分数 + 图路径，写进 `BLIND-RESULT.md`。

## 5. 失败后的处理

| 现象 | 处理 |
|---|---|
| 方向整体反读 | 删除所有 1px 尖角；钝头化，或反过来把尖头做成前端；加"前脸最亮" |
| 状态互换 | 改成物理直喻（墙/两行空/亮缝/连续流），禁止用缝/谷/肋 |
| 温度分不清 | 加形状线索（霜点/蒸汽孔），不要只改色 |
| 含量读成"散" | 减小包围盒、保持单连通；不要用透明度/粒子数 |
| 射程读不出 | 改成离散计数（3 个点/3 段），位置固定、与含量解耦 |

## 6. 已踩过的坑

1. **tile 尺寸不一致**：64×64 的 tile 被当成 16×16 裁切，整张表只剩左上角，评审看到"空框"。
   → 盲测前统一 `resize((16,16), NEAREST)` 并检查 alpha。
2. **编号压图**：编号写在 tile 上会遮住 1–2px 关键线索，评审把数字当成图形。
   → 用 24×28 画布、顶部 9px 留白。
3. **带底 tile**：不透明背景会让 bbox/面积统计失效（全 256）。
   → 只用透明 RGBA tile 做统计。
4. **一张表问两个属性**：评审会用 A 的线索推 B。
   → 一表一属性。
